# 저장된 메르 입력으로 판단 모델 비교

`compare_decisions.py`는 Gemini 기존 판단, 문맥 개선 Gemini 판단, 문맥 개선 ChatGPT 판단을 같은 입력 스냅샷으로 비교하는 실험 도구다. 기존 자동 운영의 제공자는 Gemini이며 이 도구가 운영 제공자를 바꾸지 않는다.

## 기본 실행: API 호출 없는 입력 검사

```bash
python compare_decisions.py --dry-run
```

기본 명령은 저장된 `output/posts_db.json`의 요약과 `output/portfolio_state.json`만 읽는다. 글 수집, 요약 재생성, 토큰 계산 API, 판단 API, Telegram 전송, 포트폴리오 상태와 수익률 원장 갱신을 실행하지 않는다. `main.py`의 `verify` 모드는 Telegram을 전송할 수 있으므로 이 비교 도구의 대체로 사용하지 않는다.

결과는 `experiments/comparison-날짜-시간/comparison.json`에 저장한다. 운영 `output/` 아래를 결과 위치로 지정하면 실행을 거부한다. 실행 전후 운영 파일의 해시를 비교하고 변경이 발견되면 명령이 실패 코드 2를 반환한다. 이미 변경된 파일을 자동으로 복원하지 않는다.

외부 `--source-dir`을 사용해도 입력 스냅샷과 저장소의 실제 `output/`을 모두 검사한다.
결과가 모두 `dry-run` 또는 `valid`이면 종료 코드 0, 입력 차단·판단 보류·예산 소진으로
미완료된 비교는 1, 운영 파일 변경은 2다. 실패 결과도 아티팩트에 기록한다.

## 입력 시점과 범위

- `--run-type regular`가 기본이다. 저장된 `pending` 글 중 최신 요약 v4, 투자 관련, 요약 완료 조건을 충족하는 글을 사용한다. 새 글 수집이 없으므로 신규 URL은 추가하지 않는다.
- `--run-type rebalance`는 저장된 마지막 리밸런싱 날짜 이후 글을 사용한다. 이전 날짜가 없으면 기존 14일 출처 범위를 적용한다. 범위에 요약 보류 또는 구버전 요약이 있으면 전체 비교를 보류한다.
- 분석일 이후에 게시된 글은 제외한다. 현재 상태의 판단·출처 발행·신호 생성 날짜보다 과거 날짜를 지정하면 거부한다. 관찰된 정보 날짜를 확인하는 규칙이며 예정된 관심종목 만료일은 미래 정보로 취급하지 않는다. 역사적 성과 비교에는 그 날짜에 실제로 사용 가능했던 요약과 계좌 상태 스냅샷을 따로 준비해야 한다.
- 캐시의 인용문을 원문과 같은 정규화 규칙으로 다시 대조한다. 인용문이 원문에 없으면 모델을 호출하지 않는다. 준비된 신호, 입력 상태와 날짜는 모든 제공자에 동일한 복사본으로 전달한다.

`--analysis-date YYYY-MM-DD`, `--source-dir 경로`로 입력 날짜와 별도 스냅샷 디렉터리를 지정할 수 있다. 디렉터리에는 `posts_db.json`과 `portfolio_state.json`이 필요하다. 분석일 기본값은 한국 날짜다.

## 명시적인 실모델 비교

```bash
python compare_decisions.py --live --max-requests 3 --repetitions 1
```

실제 호출은 `--live`가 있어야 가능하다. Gemini는 기존 `GEMINI_API_KEY`와 모델 설정을 사용한다. ChatGPT는 별도 공식 로그인 모듈의 최초 인증이 필요하다. 로그인 정보와 API 키를 비교 JSON 또는 저장소에 넣지 않는다.

세 비교 변형은 다음과 같다.

| 변형 | 판단 제공자 | 문맥 |
|---|---|---|
| `gemini-baseline` | 기존 Gemini | 기존 입력 구성 |
| `gemini-focused` | Gemini | 원문 신호와 활성 판단을 보존하고 반복 이력을 줄인 실험 입력 |
| `chatgpt-focused` | ChatGPT 로그인 | 동일한 개선 입력 |

`--variants gemini-baseline gemini-focused`로 비교 대상을 줄이고, `--gemini-model`, `--chatgpt-model`로 실험 모델만 지정할 수 있다. 기본 Gemini 운영 모델을 덮어쓰지 않는다.

`--max-requests`는 전체 비교에서 실제 생성 요청 시도 직전에 차감하는 공통 상한이다. 전송 실패, 재시도, JSON 교정도 요청 시도에 포함한다. 세 변형에 각 1회가 필요해도 첫 변형이 재시도를 소모하면 이후 변형은 생략될 수 있다. 남은 일일 무료 한도는 이 상한으로 조회할 수 없으며 Google AI Studio에서 따로 확인해야 한다. 제공자별 토큰 계산 요청은 생성 요청 횟수와 별개다.

## 무엇을 검증하는가

결과에는 입력·운영 파일 해시, 판단 스키마·시스템 프롬프트·관련 코드의 해시, 인용문 일치 수, 변형별 문맥 문자 수, 날짜와 실행 유형, 실제 생성 시도 수, 검증 결과, 제공자 응답 사용량이 제공된 경우 그 값, 기존 상태 및 첫 유효 Gemini 기준 결과와 종목·비중 차이를 기록한다. 문맥 문자 수는 제공자별 전달 형식과 스키마 추가 전의 사용자 메시지 길이다. 전체 모델 입력 토큰이나 시스템 프롬프트 길이가 아니다. 원문 모델 응답은 저장하지 않고 오류의 자격 증명 형태 문자열은 가린다.

판단 결과는 기존 재조정 보유 종목 검토, 출처·방향 적합성 연결, 신규 종목의 검증된 근거, 상태 스키마, 기존 비중 상한·현금 정책을 메모리 안에서 검사한다. 실험은 시장 데이터 조회를 하지 않으므로 종목의 최신 거래 가능 여부와 실가격은 추가 검증 대상이다.

문자 수 감소를 토큰 수 감소 또는 수익률 개선으로 표현하지 않는다. JSON이 유효한 응답, 원문 근거에 부합하는 응답, 수익률이 높은 전략은 서로 다른 평가다. 수익률은 시점별 가용 입력·가격·비용·매매 규칙을 고정한 별도 검증 전에는 개선됐다고 판단하지 않는다.

수동 GitHub 실행과 최초 로그인은 [연결 안내](chatgpt-login.md), API 없는 실제 캐시 검사와
모의 모델 교정 테스트는 [2026-10-06 검증 기록](validation/chatgpt-provider-20261006.md)을 참고한다.

`메르 Gemini 실모델 비교 (운영 상태 유지)`는 저장소의 기존 Gemini 키로 두 Gemini
경로를 호출하는 별도 워크플로다. ChatGPT 인증이 필요 없고 최초 검증의 생성 상한은
4회다. 기능 브랜치에서 해당 워크플로 파일을 변경할 때만 자동 실행하며, 검증 기록과
일반 코드·문서 갱신은 새 호출을 만들지 않는다.

최초 양쪽 경로 비교는 실제 4회 응답을 받았지만 두 경로 모두 근거 검증에 실패했다.
오류 안내를 보완한 v2 재검증에서는 `focused` 경로·2회 상한이 워크플로 기본값이다.
수동 `variants=both`, `max_requests=4`로 양쪽 경로를 비교할 수 있다.
